# sns-relay — 블로그 글·글감 → SNS 채널별 초안

프로그램(`sns-relay` CLI)이 본문 추출, 링크(UTM), 검증, 승인·게시·게시 기록을 맡는다. 너는 **초안 본문만** 쓴다.

명령이 설치되어 있지 않으면(`sns-relay --version` 실패) 오너에게 설치를 권한다: `git clone https://github.com/SomySam/sns-relay.git` → 그 폴더에서 `npm install` → `npm install -g .` (설치 전이라면 `node <저장소>/dist/cli/index.js` 를 대신 쓴다).
작업 폴더가 현재 폴더가 아니면 모든 명령에 `--dir <작업 폴더>` 를 붙인다.

## 절차

1. **작업 폴더 확인.** 현재 폴더에 `config.json` 이 없으면 오너에게 이 폴더를 작업 폴더로 쓸지 묻고, 괜찮으면 `sns-relay init` 을 실행한다.
2. **글감·사진으로 시작할 때.** `sns-relay new --title "<제목>" --text <글감 파일> [--image <파일 또는 주소>] [--link <주소>]`. 글감은 오너가 준 말을 그대로 파일로 저장한다. 로컬 사진은 imageHost: cloudinary 가 필요하다. 입력창에 올린 사진이 여러 장이면 올린 순서대로 `--image` 를 여러 번 준다(첫 장이 대표, 최대 10장). 이 경우 아래 글 가져오기는 건너뛴다.
3. **글 가져오기.** `sns-relay fetch <글 주소>` 를 실행한다. 출력의 작업 이름(`<id>`)을 기억한다. 채널별 빈 초안 파일 `work/<id>/drafts/<channel>.md` 가 만들어진다.
4. **규칙 읽기.** `sns-relay rules` 의 출력을 끝까지 읽는다. 이 규칙이 초안 품질의 기준이다.
5. **원문 읽기.** `work/<id>/article.json` 의 `title` 과 `text` 를 읽는다. 본문은 이것 한 번만 읽는다(블로그 페이지를 따로 열지 않는다). (글감 작업도 article.json 의 text 가 원문이다)
6. **초안 쓰기.** 채널별 초안 파일에서 아래쪽 `---` 다음 본문만 채운다.
   - 위쪽 `---` 사이(frontmatter)의 `channel`, `approved`, `link`, `image` 는 건드리지 않는다.
   - 네이버 초안만 `title` 과 `tags` 를 규칙에 맞게 고친다.
   - 본문에 주소(URL)를 쓰지 않는다. 링크는 프로그램이 붙인다.
7. **검증.** `sns-relay drafts <id>` 를 실행한다.
   - `✖` 오류가 있으면 고치고 다시 확인한다.
   - `⚠` 경고는 오너에게 알려 준다.
   - 글자 수 제한은 `drafts` 가 보여 주는 글자 수(공백·줄바꿈 포함)를 기준으로 한다.
8. **오너 검토.** 채널별로 초안 본문과, `drafts` 가 출력한 제목·태그(네이버)·링크·이미지 줄을 오너에게 그대로 보여 준다. 수정 요청이 오면 파일을 고치고 7번부터 다시 한다.
9. **승인.** 오너가 **명시적으로** 승인한 채널만 `sns-relay approve <id> --channels <채널,...>` 로 승인한다(전부 승인했더라도 `--channels` 에 승인된 채널을 빠짐없이 직접 나열한다).
   - 승인 여부를 추측하지 않는다. 오너가 "좋아요"라고만 하면 어느 채널을 승인할지 되묻는다.
   - `approved: true` 를 파일에 직접 쓰지 않는다. 그렇게 해도 프로그램이 승인으로 인정하지 않고 되돌린다.
   - 승인 뒤 본문을 고치면 승인이 자동으로 풀린다. 다시 오너 확인을 받는다.
10. **게시 미리보기.** 오너가 게시를 원하면 `sns-relay publish <id> --dry-run` 을 실행하고, 채널별 최종 문구와 링크를 그대로 보여 준다. 지금 자동 게시는 Threads·인스타그램·페이스북 페이지가 된다. 인스타그램은 미리보기에서 이미지 확인 결과(✔/✖/⚠)를 오너에게 함께 보여 준다.
    - 대표 이미지가 JPEG 가 아니면 `sns-relay image <id> --article` 로 Cloudinary 에 옮겨 JPEG 로 바꾼다(승인이 풀리므로 다시 확인).
11. **게시.** 오너가 **명시적으로** "올려"라고 한 채널만 `sns-relay publish <id> --channels <채널,...>` 로 게시한다.
    - `--channels` 없이 실제 게시하면 프로그램이 거부한다. 오너가 승인한 채널을 항상 이름으로 적는다.
    - 게시는 되돌릴 수 없다. 미리보기 없이 게시하지 않는다.
    - 결과의 게시물 주소를 오너에게 알려 준다.
    - 사진 여러 장(캐러셀)은 준비에 몇 분 걸릴 수 있다. 응답이 늦거나 status 가 아직 승인됨으로 보여도 다시 게시하지 말고 몇 분 뒤 status 로 확인한다.
    - `? 결과 불명` 이 나오면 다시 게시하지 않는다. 오너에게 채널에서 게시 여부를 확인해 달라고 한다. 그 답에 따라 `sns-relay resolve <id> <채널> --published <게시물 주소>` 또는 `--not-published` 를 실행한다. 게시된 경우 게시물 주소는 반드시 오너에게 물어서 받는다.
    - `✖ 실패` 는 사유(토큰 만료·한도 등)를 오너에게 전한다. 원인을 고친 뒤 같은 명령으로 다시 게시할 수 있다.
    - 토큰·권한 오류로 실패하면 `sns-relay doctor` 로 점검해 결과를 오너에게 보여 준다. Threads·Instagram 토큰 만료가 가까우면 오너에게 `sns-relay token refresh <채널>` 을 권한다.
12. **네이버(반자동).** 네이버는 자동 게시가 없다. 오너가 네이버 발행을 원하면 다음 순서로 한다.
    - `sns-relay naver <id>` 를 실행한다. 붙여 넣기용 원고(`work/<id>/naver.md`)가 만들어져 기본 앱으로 열린다. 클립보드에는 아무것도 복사하지 않는다. 제목과 태그 목록을 오너에게 보여 준다.
    - 오너에게 네이버 블로그 글쓰기를 열어 달라고 한다. 오너가 원고 파일에서 칸별로 복사해 제목 → 본문 순으로 붙여 넣는다.
    - 오너가 소제목 서식을 입힌다.
    - 발행 버튼을 누르면 뜨는 발행 설정 창의 「태그 편집」에는 태그를 하나씩 입력하고 Enter 로 확정해야 한다(쉼표로 이어 붙이면 한 태그가 된다). 오너가 원고 파일 끝의 태그 목록을 보고 직접 입력한 뒤 발행한다.
    - 오너가 발행한 글 주소를 알려 주면 `sns-relay mark naver <id> --url <발행 주소>` 로 기록한다.
    - 네이버에 자동으로 글을 올리려고 하지 않는다(약관 위반).
13. **마무리.** `sns-relay status <id>` 로 채널별 상태를 보여 주고 끝낸다.

## 후킹·문투 바꾸기

- 이번 글만 바꾸고 싶으면 대화로 요청한다(예: "스레드 첫 문장 후킹 3안"). 채널별로 현재 첫 문장과 3안을 보여 주고, 오너가 고른 안으로 첫 문장만 고쳐 저장한다. 내용이 바뀌면 승인이 풀리므로 다시 오너 승인을 받는다. 이미 게시된 칸은 고치지 않는다.
- 계속 적용하고 싶으면 작업 폴더 `config.json` 의 `notes`(`common` 은 모든 채널, 채널 이름은 그 채널만)에 말투를 적는다.

## 하지 말 것

- 원문에 없는 사실, 판매 문구, 과장을 넣지 않는다(규칙의 공통 절).
- `.env` 를 열거나 그 내용을 출력하지 않는다. 토큰이 들어 있다.
- 오너 승인 없이 `sns-relay approve` 를 실행하지 않는다.
- 오너가 게시하라고 하기 전에 `sns-relay publish` 를 --dry-run 없이 실행하지 않는다.
- 네이버 블로그에 브라우저 조작 등으로 자동 게시하지 않는다.
